# Accessibility Checklist: MasterSmith MVP

準拠レベル: WCAG 2.1 AA(rough-mockupsから変更なし。Q7)。`.claude/knowledge/aidlc-design-agent/accessibility-wcag.md` のPOUR原則に基づくチェックリスト。対象は全画面(wireframes.md 1.〜8. + mockups.md 9.〜13.)。レスポンシブ対応は必須ではない(デスクトップ主体、Q6)ため、タッチターゲットサイズ等モバイル固有の項目は対象外とする。

## Perceivable(知覚可能)

| 項目 | 対応方針 | 対象画面 |
|---|---|---|
| テキストコントラスト比 4.5:1以上(通常文字)、3:1以上(大文字) | `make-you-chic-ui` のテーマトークンで担保。4軸テーマ切替時も全テーマでAA準拠を確認する | 全画面 |
| 色のみに依存しない情報伝達 | ステータス表示(有効/無効化済、貸出中/在庫あり等)はテキストラベルを併記し色のみに依存しない。監査ログのアイコンボタンにも文字ラベルを併記 | 一覧画面(3.)、アカウント一覧(13a.)、監査ログ(12.) |
| 非装飾画像のalt属性 | Cardアイコン等に説明的なalt textまたは`aria-label`を付与 | トップ画面(2.) |

## Operable(操作可能)

| 項目 | 対応方針 | 対象画面 |
|---|---|---|
| キーボードのみで全機能を操作可能 | 全フォーム・全ボタン・全モーダルでTab/Enter/Space/矢印キー/Escapeによる操作を保証 | 全画面 |
| フォーカスインジケータ可視 | `outline: none` の使用を禁止し、2px以上のアウトラインで3:1以上のコントラストを確保 | 全画面 |
| 論理的なタブ順序 | 視覚的レイアウトに沿った順序(左上→右下)。モーダル(FK参照検索 9.、設定インポート確認 8.)ではフォーカストラップ内に限定 | 全画面、特にモーダル系 |
| モーダルのフォーカストラップ・Escape対応 | FK参照検索モーダル(9.)、設定インポート確認(8.)、監査ログ削除確認(12.)のいずれもEscapeで閉じ、閉じた後はトリガー要素へフォーカスを戻す | 9., 8., 12. |
| タブパネルのキーボード操作 | 設定管理画面(10.)・ロール編集画面(7b.)のタブは矢印キーで切替、WAI-ARIA Tabsパターンに準拠 | 10., 7b. |

## Understandable(理解可能)

| 項目 | 対応方針 | 対象画面 |
|---|---|---|
| フォーム入力欄のラベル明示 | 全フィールドに可視ラベル(placeholderのみに依存しない) | 編集画面(5.)、アカウント編集フォーム(13b.)、設定管理タブ(10.) |
| エラー内容の具体的な文言表示 | 「ログインIDまたはパスワードが正しくありません」「ログイン試行回数が上限に達しました」等、原因と対処が分かる文言(raw error codeを表示しない) | ログイン画面(1.)、全編集系画面 |
| 破壊的操作の事前説明 | アカウント無効化(13b.)・監査ログ削除(12.)・設定インポート(8.)はいずれも実行前に影響範囲を明示する(確認ダイアログまたは`aria-describedby`) | 13b., 12., 8. |
| 一貫したナビゲーション | パンくず・サイドナビの位置・構造を全画面で統一 | 全画面 |

## Robust(堅牢)

| 項目 | 対応方針 | 対象画面 |
|---|---|---|
| 適切な見出しレベル(h1から順に) | 各画面はh1を1つ持ち、パンくずはh1の前に配置(wireframes.mdの既定方針を踏襲) | 全画面 |
| ARIAロールの適切な使用(ネイティブHTML優先) | モーダルは`dialog`、タブは`tablist`/`tab`/`tabpanel`、通知は`alert`または`aria-live` | 9., 10., ログイン画面のロック通知 |
| 動的コンテンツの読み上げ通知 | 検索結果件数・保存完了・削除完了は`aria-live="polite"`(緊急度の高いロック通知のみ`assertive`) | 全画面(状態変化を伴うもの) |

## 管理者専用画面のアクセス制御表示(R-02フォロー)

- 設定管理(10.)・スキーマ取り込み(11.)・監査ログ(12.)・アカウント管理(13.)は管理者ロール(FR5.5)専用の画面であり、非管理者にはトップ画面(2.)のサイドナビにこれらの項目自体を表示しない。
- URL直接指定等で非管理者がアクセスした場合は、各画面のerror状態として「この操作を行う権限がありません」を表示する(一覧画面3./詳細画面4.の既存パターンと同一の文言)[FR5.6]。

## 新規画面固有の確認事項(mockups.md 9.〜13.)

- FK参照検索モーダル(9.): モーダル内テーブルの行選択が、マウスクリックだけでなくキーボード(Enter)でも選択操作として機能すること。
- スキーマ取り込みプレビュー(11.): ビュー(view)であることを、色だけでなくテキストラベル(「(view, PKなし)」)で明示すること(rough-mockupsレビューR-01フォロー)。
- 監査ログ画面(12.)・アカウント一覧(13a.): 一覧画面(3.)と同一のTableコンポーネントを再利用するため、既存の`aria-sort`実装をそのまま踏襲できる。
- ログイン試行制限表示: `aria-live="assertive"`とするが、頻発するとスクリーンリーダー利用者の妨げになるため、同一メッセージの再アナウンスは抑制する(連続失敗のたびに毎回読み上げない)よう実装時に留意する **[assumption]**。

## 未実施の検証(後続段階)

- 自動スキャン(axe DevTools、Lighthouse)によるコントラスト比・ARIA属性の機械検証は、Construction段階(Build and Test)で実施する。
- スクリーンリーダー(VoiceOver/NVDA)での実機検証は本ドキュメント作成時点では未実施であり、後続段階の課題として残す。
