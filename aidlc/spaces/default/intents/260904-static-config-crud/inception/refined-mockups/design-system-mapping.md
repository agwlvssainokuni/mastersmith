# Design System Mapping: MasterSmith MVP

対象デザインシステム: 自作 `make-you-chic-ui`(https://github.com/agwlvssainokuni/make-you-chic-ui.git、React/TSX、プロトタイプ段階)。既存コンポーネント(AppShell、Table、フォーム部品群、4軸テーマ機構)を最大限再利用し、不足するものは新規追加候補として明示する。

## 既存コンポーネントの再利用

| 画面/要素 | make-you-chic-ui コンポーネント | 備考 |
|---|---|---|
| 全画面共通のシェル(Topbar・サイドナビ・コンテンツ領域) | `AppShell` | wireframes.md 2.〜8.、mockups.md 9.〜13. すべてで再利用 |
| 一覧画面のテーブル(3.、12.、13a.) | `Table`(ソート・ページング対応) | 監査ログ画面(12.)・アカウント一覧(13a.)も同一コンポーネント |
| 検索・フィルタ入力群 | `TextField`、`Select` | 一覧画面・監査ログ画面・FK検索モーダル共通 |
| フォーム部品(編集画面) | `TextField`、`Textarea`、`Checkbox`、`Switch`、`RadioGroup`、`Select` | 編集画面(5.)・アカウント編集フォーム(13b.)・設定管理タブ(10.)のマトリクス内セルで再利用 |
| テーマ切替 | 4軸テーマ機構(業務インスタンスごとの配色作り分け、wireframes.md冒頭で言及) | トップ画面(2.)のTopbarに配置。具体的な4軸の定義値はドメイン設計以降で確定 |
| 確認ダイアログ | `ConfirmDialog`(設定インポート確認 8. で既に使用) | 監査ログの保持期間超過削除確認(12.)でも再利用。`ConfirmDialog`が汎用`Modal`プリミティブの上に構築されているか、独立実装かは本ドキュメント作成時点で未確認 **[assumption]**(下記「新規追加が必要なコンポーネント候補」の`Modal`と合わせて確認する) |
| タブ | `Tabs`(ロール編集画面 7b. で既に使用) | 設定管理画面(10.)で再利用 |
| アコーディオン | `Accordion`(グループ管理画面 7e. で既に使用) | 本ラウンドでの新規画面には追加利用なし |

## 新規追加が必要なコンポーネント候補

| 画面/要素 | 候補コンポーネント名 | 理由 |
|---|---|---|
| FK参照検索モーダル(9.) | `Modal` + 内部に `TextField`/`Select`/`Table` を組み合わせ(既存の`ConfirmDialog`が汎用`Modal`の上に構築されていれば、そのコンテナを流用して検索UIを内包する拡張とする。`ConfirmDialog`が独立実装であれば、汎用`Modal`コンテナを新規に追加する必要がある) | `make-you-chic-ui` に汎用モーダル(`Modal`)が独立コンポーネントとして存在するか未確認。上記`ConfirmDialog`の実装確認結果に応じて、拡張(既存流用)か新規追加かが決まる **[assumption]** |
| スキーマ取り込みプレビュー(11.) | `CheckableList`(チェックボックス付きリスト) | 既存コンポーネント一覧に相当するものが見当たらないため、新規追加候補とする **[assumption]** |
| 設定管理タブ内のマトリクス(10.) | `MatrixGrid`(行×列のチェックボックス/ラジオグリッド、ロール編集画面7bで既に使用しているものと同一) | 既存の`Tabs`内で使われている構造を流用できる想定だが、コンポーネントとして独立しているかは未確認 **[assumption]** |

## 未確認事項

- `make-you-chic-ui` は未公開・プロトタイプ段階のリポジトリであり、実際のコンポーネントAPI(props名・型)は本ドキュメント作成時点で参照できていない。上記のマッピングはwireframes.md/rough-mockups段階で確認された「ほぼ部品はカバーしているはず」という開発者自身の認識に基づく仮定であり、ドメイン設計・コード生成段階で実際のコンポーネントAPIと突き合わせて確定する **[assumption]**。
- 新規追加候補(`Modal`、`CheckableList`)が実際に存在しない場合、その実装(または汎用HTML+ARIAでの代替実装)の要否は、ドメイン設計段階で判断する。
