# Scalability Design: audit-log

## スケーリングアーキテクチャ

単一インスタンス構成(NFR2)。水平スケーリング・ロードバランシング・データパーティショニング/シャーディングは設計しない。

## データ量増加への対応

AuditLogEntryは保持期間超過分の一括削除(BR4.1、既定365日)により、無制限な増加を防ぐ。想定運用規模(自宅サーバ1台・個人利用)では、365日分のレコード数がスケーラビリティ上の課題になることはない。

## 容量閾値

明示的な容量閾値・オートスケーリングルールは設けない。運用者が保持日数(retentionDays)をPUT /api/admin/audit-log/settingsで調整することで、蓄積量を制御する。
