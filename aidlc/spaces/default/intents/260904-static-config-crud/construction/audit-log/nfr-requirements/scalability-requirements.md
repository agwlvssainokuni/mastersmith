# Scalability Requirements: audit-log

## NFR2.1: 単一インスタンス・単一業務前提

requirements.md NFR2を踏襲する。1インスタンス=1業務であり、単一インスタンスでの複数業務同時提供(マルチテナント運用)は行わない。したがって、audit-logのデータ量・アクセス量は単一業務の運用規模に閉じる。

## NFR2.2: データ量の増加対策

監査ログのデータ量増加は、水平/垂直スケーリング等のインフラ的な対策ではなく、保持期間ポリシー(BR4.1、既定365日、管理者が変更可能)による定期的な削除で制御する。これは自宅サーバ1台という実行環境(team.md)に適した、運用側での増加抑制策である。

## N/A: 追加のスケーリング機構

負荷分散・オートスケーリング・シャーディング等の追加のスケーラビリティ機構は、本プロジェクトの想定運用規模(個人利用中心)に照らして不要と判断する。
