# Scalability Requirements: config-management

## NFR2.1: 単一インスタンス・単一業務前提

requirements.md NFR2(1インスタンス=1業務、マルチテナンシーなし)を踏襲する。DbConnection・TableConfig・MenuItemのレコード数は、当該業務インスタンスが管理するテーブル数・メニュー構成規模に比例する。自宅サーバ1台・個人利用中心という想定運用規模では、これらのテーブルサイズおよびCaffeineキャッシュのメモリ使用量が性能上の課題になることはない。

## NFR2.2: キャッシュサイズの想定

Caffeineキャッシュ(BR6.1)は、想定運用規模(1業務あたり数十〜数百テーブル程度)ではメモリ使用量が問題にならない。将来的にテーブル数が大幅に増加した場合は、Caffeineの最大エントリ数設定(maximumSize)によるキャッシュ制御を検討する余地があることを記録しておく。
