# Reliability Design: config-management

自宅サーバ1台構成のため、SLA/SLO数値目標は設けない。

## 設定インポート時の全体拒否

設定インポート(BR5.2)は、不正形式・スキーマ不一致・必須項目欠落のいずれかを1件でも検出した場合、設定全体の適用を拒否し(部分適用を行わない)、検出した全件をerrors配列として返す。サービスコンポーネントは検証を最初の1件で打ち切らず最後まで行う(NFR-CONSISTENCY.1)。

## キャッシュとDBの整合性

サービスコンポーネントは、設定の作成・更新・削除の都度、リポジトリへの書き込みに続けて該当キャッシュエントリを明示的に無効化する(BR6.2、NFR-CONSISTENCY.2)。インポート成功時はキャッシュ全体をクリアする(BR5.3)。この順序(DB書き込み→キャッシュ無効化)により、キャッシュがDBの内容と乖離した状態で読み取られることを防ぐ。

## schema-ingestion呼び出し失敗時の扱い

サービスコンポーネントが行うschema-ingestionへのプロセス内呼び出し(契約#1、スキーマ取り込み)自体が失敗(業務DB接続失敗等)した場合、この例外を握りつぶさずそのまま伝播させ、RESTコントローラは500として応答する(NFR-FAILSAFE.1)。リトライは行わない。

## ヘルスチェック

Spring Boot Actuatorの標準`/actuator/health`エンドポイントに委ねる。
