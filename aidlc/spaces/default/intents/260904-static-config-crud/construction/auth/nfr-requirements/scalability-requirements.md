# Scalability Requirements: auth

## NFR2.1: 単一インスタンス・単一業務前提

requirements.md NFR2(1インスタンス=1業務、マルチテナンシーなし)を踏襲する。Account・RefreshToken・AccountActionTokenのレコード数は、当該業務インスタンスの登録利用者数に比例する。自宅サーバ1台・個人利用中心という想定運用規模では、これらのテーブルサイズが性能上の課題になることはない。

## NFR2.2: リフレッシュトークンの増加傾向

リフレッシュトークンローテーション(BR3.2)により、アクセストークンの更新のたびに新規RefreshTokenレコードが発行され、古いレコードはrevoked=trueとして残る(物理削除は行わない、functional-spec.md参照)。想定運用規模では蓄積量は問題にならないが、将来的に肥大化した場合は失効済み・期限切れレコードの定期削除(バッチ)を検討する余地があることを記録しておく。
