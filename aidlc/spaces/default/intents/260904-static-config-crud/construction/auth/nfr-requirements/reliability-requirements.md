# Reliability Requirements: auth

自宅サーバ1台構成のため、SLA/SLO数値目標(稼働率%等)は設けない(requirements.md NFR1、team.md Deployment)。

## NFR-FAILSAFE.1: ログインロックと可用性のトレードオフ

ログイン失敗回数が既定n=5回に達すると既定m=300秒のロックを設定する(BR4.1)。この間は正規の利用者であってもログインできなくなる(BR4.2)。これは総当たり攻撃耐性というセキュリティ目的との明示的なトレードオフとして許容する。ロックはlockedUntil経過により自動解除され、明示的な解除操作は設けない(BR4.2)。ロック時間(m)はapplication.ymlで調整可能なため、運用上ロックが長すぎると判断した場合は設定変更で対応する。

## NFR-FAILSAFE.2: permission呼び出し失敗時の扱い

ログイン処理は契約#20経由でpermissionへ有効ロール一覧を問い合わせる(BR2.1)。permission呼び出し自体が失敗した場合はエラーとして呼び出し元(client)へ伝播し、5xxとして応答する(BR2.1違反時挙動)。空のロール一覧が返る場合(利用者にロール未割当)はエラーとせず、ログイン自体は成功として扱う。
