# Reliability Design: auth

自宅サーバ1台構成のため、SLA/SLO数値目標は設けない。

## ログインロックと可用性のトレードオフ

ログイン失敗回数が既定n=5回に達すると既定m=300秒のロックを設定する(BR4.1)。この間は正規の利用者であってもログインできなくなる(BR4.2)。これは総当たり攻撃耐性というセキュリティ目的との明示的なトレードオフとして許容する。ロックはlockedUntil経過により自動解除され、明示的な解除操作は設けない。

## permission呼び出し失敗時の扱い

サービスコンポーネントが行うpermission Unitへのプロセス内呼び出し(契約#20、有効ロール取得)自体が失敗(内部H2接続断等)した場合、この例外を握りつぶさずそのまま伝播させ、RESTコントローラは5xxとして応答する。permission呼び出しが空のロール一覧を返す場合(利用者にロール未割当)はエラーとせず、ログイン自体は成功として扱う(BR2.1、両者を明確に区別する)。

## リトライ・サーキットブレーカー

リトライは行わない。auth自身は他Unit(permission)への呼び出しを1回のみ行い、失敗時は即座に呼び出し元へエラーを返す。サーキットブレーカーは設計しない(プロセス内呼び出しであり、ネットワーク越しの呼び出しに特有の障害モードを想定する必要が薄いため)。
