# Scalability Design: auth

## スケーリングアーキテクチャ

単一インスタンス構成(NFR2.1)。水平スケーリングは設計しない。

## リフレッシュトークンの増加傾向

リフレッシュトークンローテーション(BR3.2)により、アクセストークンの更新のたびに新規RefreshTokenレコードが発行され、古いレコードはrevoked=trueとして残る(物理削除は行わない、functional-spec.md参照)。想定運用規模では蓄積量は問題にならないが、将来的に肥大化した場合は失効済み・期限切れレコードの定期削除(バッチ)を検討する余地があることを記録しておく(本ステージのスコープ外)。
