# Performance Design: schema-ingestion

## 応答速度の一般方針

requirements.md NFR1(厳密な数値目標なし)を踏襲する。

## スキーマ走査の性能設計

スキーマ走査(サービスコンポーネントのJDBC `DatabaseMetaData`呼び出し)は、テーブル数に比例して時間がかかりうるが、並列化・非同期化は行わない(単一スレッドで逐次処理する)。個人利用中心の想定業務規模(数十〜数百テーブル程度)では実用上問題ない範囲と判断する(NFR1.2)。

著しい遅延が確認された場合は、取り込み対象テーブルの絞り込み(プレビュー画面でのテーブル選択)により後段処理(config-managementでのTableConfig一括作成)の負荷を抑える設計とし、走査ロジック自体の最適化は本ステージでは規定しない。

## 接続管理

業務DBへの接続はコネクションプールを保持せず、各リクエスト(接続テスト・スキーマ一覧・プレビュー)ごとに新規接続を確立し、処理完了後にクローズする(ステートレス設計、logical-components.md参照)。
