# Reliability Design: notification

自宅サーバ1台構成のため、SLA/SLO数値目標は設けない。

## SMTP送信失敗時のリトライなし

サービスコンポーネントはSMTP送信失敗(接続不可・拒否等)をログに記録し、リトライは行わない(BR3.1、NFR-FAILSAFE.1)。イベント自体はこの時点で失われる。これは明示的なトレードオフであり、利用者本人が再操作で再試行できるフロー(パスワード忘れ・メールアドレス変更)は利用者の再実行に委ねる。管理者起点のアカウント作成通知についての再送手段はMVPスコープに含めない。

## リトライ・サーキットブレーカー

リトライは行わない。サーキットブレーカーは設計しない(SMTP送信は都度独立した試行であり、連続呼び出しによる障害波及を防ぐ必要性が低いため)。

## ヘルスチェック

Spring Boot Actuatorの標準`/actuator/health`エンドポイントに委ねる。
