# Wireframes: MasterSmith MVP

低精細(ラフ案)ワイヤーフレーム。レイアウト・構造・情報階層に集中し、業務ごとのテーマ作り分け(ブランドカラー等)はRefined Mockups以降で検討する [Q6]。対応デバイスはデスクトップ主体、レスポンシブ対応は必須ではない [Q4]。アクセシビリティはWCAG 2.1 AA相当を基本方針とする [Q5]。

```
+---------------------------------------------+
```
<!-- Text fallback: 中央に「MasterSmith」タイトル、Email/ID入力欄とPassword入力欄、Log inボタン、パスワード忘れリンク。 -->

**Accessibility**: 見出しレベル h1(「MasterSmith」)。ランドマークは `main`(フォーム全体)。キーボード入力の起点はEmail/ID入力欄(ページロード時にフォーカス)。

### 5つの画面状態

| 状態 | 内容 |
|---|---|
| empty | 該当なし(フォームは常に同じレイアウト) |
| loading | ログイン処理中はLog inボタンをdisabledにし処理中表示 |
| success | 認証成功、トップ画面へ遷移 |
| error | Email/ID・パスワードが誤っている場合、フォーム上部に「ログインIDまたはパスワードが正しくありません」を表示(どちらが誤りかは示さない、利用者列挙を防ぐセキュリティ上の配慮。入力欄ラベル「Email/ID」と表現を揃える) |
| partial | 該当なし |

## 2. トップ画面(テーブル・メニューのカード一覧)

実行インスタンスは業務ごとに分ける方式(feasibility Q4)のため、1つのインスタンスは1つの業務のみを扱う。トップ画面のCard一覧は、その業務(このインスタンスの設定)内のテーブル・メニュー項目を並べるものであり、複数の業務ドメインを並べるものではない。以下は「蔵書管理」インスタンスの例。

```
+---------------------------------------------+
| [蔵書管理 - MasterSmith] [Theme] [User menu v]|
+--------+--------------------------------------+
| (side  |  Tables / Menu                       |
|  nav,  |  +----------+ +----------+ +--------+ |
|  可縮小)|  | 書籍      | | 会員     | | 貸出   | |
|        |  | (一覧へ)  | | (同左)   | | (同左) | |
|        |  +----------+ +----------+ +--------+ |
+--------+--------------------------------------+
```
<!-- Text fallback: 上部にAppShellのTopbar(このインスタンスの業務名・テーマ切替・ユーザーメニュー)、左にサイドナビ(縮小可能)、右のコンテンツ領域にTables/Menuの見出しと、このインスタンス(例: 蔵書管理)に設定されたテーブル・メニュー項目(書籍・会員・貸出等)のCardが横に並ぶ。各Cardを選択すると、そのテーブルの一覧画面へ遷移する。家電EC・ポイント管理は、それぞれ別インスタンスとして同様のトップ画面を持つ(このインスタンスには表示されない)。 -->

**Accessibility**: 見出しレベル h1(「Tables / Menu」)。ランドマークは `header`(Topbar)・`nav`(サイドナビ)・`main`(Cardグリッド)。キーボード入力の起点はサイドナビの最初の項目、またはスキップリンクでmainへ。

### 5つの画面状態

| 状態 | 内容 |
|---|---|
| empty | このインスタンスにテーブル・メニュー設定が1件もない場合、「まだテーブルが設定されていません」+設定投入を促す案内を表示 |
| loading | Card一覧をスケルトン表示 |
| success | テーブル・メニューのCardが並ぶ通常状態(上記) |
| error | 設定読み込みに失敗した場合、エラーメッセージ+再試行ボタン |
| partial | テーブルが1件のみの場合でも同じCardレイアウトで表示 |

## 6. アカウント関連画面(概要)

ログイン機能(Q13)の具体化に伴うメール駆動の画面群。詳細なワイヤーフレームはRefined Mockups以降で作り込むが、構造の骨格のみここで示す。

- **パスワード忘れ申請画面**: メールアドレス入力 → 送信 → 「メールを確認してください」という完了メッセージ
- **パスワード再設定画面**(メール内URL経由): 新しいパスワード入力欄(確認用含む) → 保存
- **アカウント作成完了画面**(メール内URL経由、管理者によるアカウント作成後): 氏名・パスワード設定欄 → 保存
- **アカウント情報変更画面**: 氏名・パスワード・メールアドレスの変更フォーム(それぞれ独立したセクション)
- **メールアドレス変更確認画面**(新アドレス宛メール内URL経由): 現在のパスワード入力欄 → 確認 → 変更完了

いずれも編集画面(5.)と同様の1カラムフォームレイアウトを踏襲する。

**Accessibility**: 編集画面(5.)に準ずる(見出しレベル h1、ランドマーク `main`、キーボード入力の起点は最初の入力欄)。詳細な個別調整はRefined Mockups以降で行う。

## 7. 権限管理画面群(ロールベース、Must-have、intent-backlog.md PU-07)

権限はロール(Role)単位で定義し、ロールをユーザまたはグループに割り当てる。1人の利用者が複数のロールを割り当てられている場合、作業時にどのロールとして振る舞うかを選択(切り替え)できる。テーブル単位の権限(一覧/詳細/新規/編集/削除)と、カラム単位の権限(更新可(既定)/表示のみ/非表示)の2軸を持つ。
