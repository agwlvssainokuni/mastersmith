# User Flow: MasterSmith MVP

## Flow 1: 中核のCRUDフロー(ハッピーパス)

```
Flow: 業務データの一覧確認から編集までの一連の操作
Persona: 開発者本人(当面の唯一の利用者)
Trigger: MasterSmithにログインし、特定の業務データを確認・更新したい
Steps:
  1. [ログイン画面] -> Email/ID・Passwordを入力しログイン -> [トップ画面(このインスタンスのテーブル・メニューのカード一覧)]へ遷移
  2. [トップ画面] -> 対象テーブル(例: 書籍)のCardを選択 -> [一覧画面]へ遷移
  3. [一覧画面] -> 検索・絞り込みを行う -> 一覧が更新される
  4. [一覧画面] -> 対象行を選択 -> [詳細画面]へ遷移(主キーのないテーブルの場合、一覧画面には新規作成・編集・削除の導線がなく、閲覧のみとなる)
  5. [詳細画面] -> Editボタンを押す -> [編集画面]へ遷移
  6. [編集画面] -> 値を変更しSaveを押す -> 保存され[詳細画面]または[一覧画面]に戻る
Success outcome: 対象データが更新され、変更内容が詳細画面(または一覧画面)に反映される
Error paths:
  - ログイン時にEmail/ID・パスワードが誤り -> [ログイン画面]上部に「ログインIDまたはパスワードが正しくありません」を表示 -> 再入力
  - 検索条件に該当データなし -> 一覧画面に「該当するデータがありません」を表示 -> 検索条件を見直す
  - 一覧画面・詳細画面・編集画面のいずれかの操作について権限がない -> 「この操作を行う権限がありません」を表示(権限はロールで管理される。Flow 5・Flow 6を参照)
  - 編集画面でバリデーションエラー -> 該当フィールド直下にエラーメッセージ -> 修正して再度Save
  - 保存時にサーバエラー -> フォーム上部にエラーメッセージ -> 再試行、または後で再編集
```

## Flow 2: パスワードを忘れた場合の再設定

```
Flow: パスード忘れ対応
Persona: 開発者本人(将来的には他の利用者も想定)
Trigger: ログイン画面で「Forgot your password?」を選択
Steps:
  1. [ログイン画面] -> "Forgot your password?"を選択 -> [パスワード忘れ申請画面]へ遷移
  2. [パスワード忘れ申請画面] -> 登録済みメールアドレスを入力し送信 -> 「メールを確認してください」という完了メッセージ
  3. (メール受信) -> メール内のURLへアクセス -> [パスワード再設定画面]へ遷移
  4. [パスワード再設定画面] -> 新しいパスワード(確認含む)を入力し保存 -> [ログイン画面]に戻る
Success outcome: 新しいパスワードでログインできるようになる
Error paths:
  - 登録されていないメールアドレスを入力 -> セキュリティ上、成功時と同じ「メールを確認してください」を表示(利用者列挙を防ぐため)
  - 再設定URLが期限切れ -> 「リンクの有効期限が切れています」+再度パスワード忘れ申請へのリンク
```

## Flow 3: 管理者によるアカウント作成〜利用者本人の登録完了

```
Flow: アカウント作成〜登録完了
Persona: 管理者(アカウント作成者)/ 新規利用者(登録完了者)
Trigger: 管理者が新しい利用者のアカウントを作成する
Steps:
  1. (管理者操作。管理者向けアカウント作成画面自体のワイヤーフレームは、Q&Aで直接確認された事項ではなく、アカウント関連画面(wireframes.md 6.)と同様に詳細をRefined Mockups以降へ先送りする執筆判断である **[assumption]**) -> アカウント作成 -> 対象者宛にアカウント作成通知メールが送信される
  2. (新規利用者操作) メール内のURLへアクセス -> [アカウント作成完了画面]へ遷移
  3. [アカウント作成完了画面] -> 氏名・パスワードを設定し保存 -> アカウント登録完了通知メールが送信される
  4. [ログイン画面] -> 設定したメールアドレス・パスワードでログイン
Success outcome: 新規利用者が自分のアカウントでログインできるようになる
Error paths:
  - 登録完了URLが期限切れ -> 「リンクの有効期限が切れています」+管理者への再作成依頼を促す案内
  - 氏名・パスワード設定でバリデーションエラー -> 該当フィールド直下にエラーメッセージ
```

## Flow 4: アカウント情報変更(氏名・パスワード・メールアドレス)

```
Flow: アカウント情報変更
Persona: ログイン済みの利用者
Trigger: 自分のアカウント情報(氏名・パスワード・メールアドレス)を変更したい
Steps:
  1. [トップ画面] -> ユーザーメニューから「アカウント情報変更」を選択 -> [アカウント情報変更画面]へ遷移
  2. [アカウント情報変更画面] -> 氏名またはパスワードを変更し保存 -> 変更内容に応じてアカウント情報変更通知/パスワード変更通知メールが送信される
  3(メールアドレス変更の場合). 新しいメールアドレスを入力し送信 -> 新アドレス宛にメールアドレス変更確認メールが送信される
  4. (新アドレスでメール受信) -> メール内のURLへアクセス -> [メールアドレス変更確認画面]へ遷移
  5. [メールアドレス変更確認画面] -> 現在のパスワードを入力し確認 -> メールアドレス変更完了
Success outcome: 変更した情報でアカウントが更新され、関係者へ通知メールが送信される
Error paths:
  - メールアドレス変更確認画面でパスワードが誤り -> 「パスワードが正しくありません」を表示し再入力を促す
  - 確認URLが期限切れ -> 「リンクの有効期限が切れています」+再度変更申請への案内
```

## Flow 5: ロールの作成・権限定義

```
Flow: ロールの作成とテーブル権限・カラム権限の設定
Persona: 権限を管理する利用者(当面は開発者本人)
Trigger: 新しいロールを作成し、テーブル・カラムの権限を定義したい
Steps:
  1. [トップ画面] -> ユーザーメニューまたはサイドナビから「ロール管理」を選択 -> [ロール一覧画面]へ遷移
  2. [ロール一覧画面] -> 「+ New」を押す(または既存ロールを選択) -> [ロール編集画面]へ遷移
  3. [ロール編集画面] -> 「テーブル権限」タブで、テーブルごとに一覧/詳細/新規/編集/削除の可否をチェックボックスで設定
  4. [ロール編集画面] -> 「カラム権限」タブで、対象テーブルを選び、カラムごとに更新可(既定)/表示のみ/非表示を設定
  5. [ロール編集画面] -> Saveを押す -> ロールが保存される
Success outcome: ロールにテーブル権限・カラム権限が設定され、このロールを割り当てられた利用者のCRUDフロー(Flow 1)での操作可否に反映される
Error paths:
  - 保存時にサーバエラー -> フォーム上部にエラーメッセージ -> 再試行
  - ロール管理画面へのアクセス権限がない -> 「この操作を行う権限がありません」を表示
```

## Flow 6: ロールの割り当てと切り替え

```
Flow: ユーザ・グループへのロール割り当て、および複数ロール保有時の切り替え
Persona: 権限を管理する利用者(割り当て側)/ ロールを割り当てられた利用者(切り替え側)
Trigger: ある利用者(またはグループ)にロールを割り当てたい。あるいは、複数ロールを持つ利用者が作業対象のロールを切り替えたい
Steps:
  1. [ロール一覧画面] -> 「Assign」ボタンを選択 -> [ロール割り当て画面]へ遷移
  2. [ロール割り当て画面] -> 割り当て先(User/Group)を選び、対象を選択し、割り当てるロールをチェックボックスで選択 -> Saveを押す -> 割り当てが保存される
  3(複数ロールを持つ利用者の操作). [任意の画面のTopbar] -> ユーザーメニューの「現在のロール」を選択し、作業したいロールに切り替える -> 以降の操作は選択したロールの権限で行われる
Success outcome: 対象のユーザ・グループにロールが割り当てられる。複数ロールを持つ利用者は、選択したロールの権限で作業できる
Error paths:
  - 保存時にサーバエラー -> フォーム上部にエラーメッセージ -> 再試行
  - ロールが1つも割り当てられていない利用者がログインした -> 「利用可能な操作がありません。管理者にロールの割り当てを依頼してください」を表示
```

## Flow 7: グループの作成・メンバー管理

```
Flow: グループの作成とメンバー編集
Persona: 権限を管理する利用者(当面は開発者本人)
Trigger: 複数の利用者をまとめてロール割り当てできるよう、グループを作成したい
Steps:
  1. [ロール一覧画面] -> 「Groups」ボタンを選択 -> [グループ管理画面]へ遷移
  2. [グループ管理画面] -> 「+ New」を押す -> グループ名を入力し保存 -> グループが作成される
  3. [グループ管理画面] -> 対象グループの行を展開する(画面遷移なし) -> インラインでメンバー(ユーザ)を追加・削除する -> その場で保存される
Success outcome: グループが作成され、ロール割り当て画面(Flow 6)の割り当て先として選択できるようになる
Error paths:
  - 保存時にサーバエラー -> フォーム上部にエラーメッセージ -> 再試行
  - 同名のグループが既に存在する -> 「同じ名前のグループが既に存在します」を表示
```

## Flow 8: 設定のエクスポート/インポート

```
Flow: 内部DBに保持された設定全体のバックアップ・復元
Persona: 開発者本人
Trigger: 現在の設定をファイルとしてバックアップしたい、または過去にエクスポートした設定ファイルから復元したい
Steps:
  1. [トップ画面] -> ユーザーメニューまたはサイドナビから「設定管理」を選択 -> [設定エクスポート/インポート画面]へ遷移
  2(エクスポート). [設定エクスポート/インポート画面] -> "Export current settings"を押す -> 現在の設定がファイルとしてダウンロードされる
  3(インポート). [設定エクスポート/インポート画面] -> ファイルを選択し"Import"を押す -> 確認ダイアログ(「現在の設定を上書きします。よろしいですか?」Cancel/Import)が表示される -> Importを選ぶと設定が反映される
Success outcome: 設定ファイルがダウンロードされる、または選択したファイルの内容が内部DBの設定に反映される
Error paths:
  - インポートファイルの形式が不正 -> 「ファイルの形式が正しくありません」を表示し、インポートは実行されない
  - インポート時にサーバエラー -> フォーム上部にエラーメッセージ -> 再試行
```
