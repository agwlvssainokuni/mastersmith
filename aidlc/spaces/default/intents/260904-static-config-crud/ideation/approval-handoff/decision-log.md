# Decision Log: MasterSmith (Ideation Phase)

Ideationフェーズ(intent-capture → feasibility → scope-definition → rough-mockups → approval-handoff)で確定した主要な決定を、決定した順に記録する。

## Intent Capture & Framing

| 決定事項 | 内容 |
|---|---|
| 課題認識 | 動的解決の複雑さ排除ではなく「業務ごとにカスタマイズできない」ことが課題(Q1・Q4) |
| 利用者 | 当面は開発者本人。将来的に他の人にも使ってもらえるものを目指す(Q2) |
| 成功の目安 | 自分の複数業務で使え、あたかも各業務用に個別開発したように見えること(Q3) |
| MasterMeisterとの関係 | 置き換えではなく、独立した別プロジェクトとして並行して存在(Q8) |
| 対象RDBMS | PostgreSQL/MySQL/MariaDB。JDBCドライバはアプリに内包(Q9) |
| 進め方 | 明確な締切なし、じっくり検証(Q10) |
| MVP範囲(初期) | 権限定義+簡易ログインをMVPに含め、フル認証基盤とデプロイ/運用は対象外(Q11〜Q13) |

## Feasibility & Constraints

| 決定事項 | 内容 |
|---|---|
| 検証方法 | 家電EC・ポイント管理・蔵書管理のテスト用スキーマ+ダミーデータで検証(Q1) |
| 技術スタック | Java 25/Spring Boot/Gradle(バックエンド)、React(TSX)のSPA(フロントエンド、make-you-chic-ui活用)(Q2・Q11) |
| コード再利用 | MasterMeisterのコードは使わず新規に書き起こす(Q3) |
| 実行インスタンス | 業務ごとに個別インスタンス(1インスタンス=1業務)(Q4) |
| スキーマ対応範囲 | 複合主キー対応、主キーなしテーブルはUPDATE/DELETE対象外、ビューは表示専用、ストアドプロシージャは対象外(Q5) |
| 認証・パッケージング | ステートレスなアクセストークン方式。単一の実行可能WARにパッケージング(Q7・Q12) |
| 権限モデルの参照元 | MasterMeisterの権限モデルを参考にする(Q8) |
| 実行環境 | 自宅サーバ、Twelve-Factor App準拠(Q9) |
| 可観測性 | OTel対応・構造化ログ(Q13) |
| 開発/実行時構成 | Viteのdevサーバproxy(開発時)、単一WARが同一オリジンでSPA配信+API提供(実行時、CORS不要)(Q14) |
| 内部データストア | 業務DBとは別にH2を採用。設定全体(9項目)・アカウント・権限を保持(Q15) |
| 静的設定駆動との両立 | キャッシュ機構(起動時読み込み、明示的クリア/expireでのみ再読み込み)(Q16) |
| 設定の可搬性 | エクスポート/インポート機能を追加(Q17) |
| メール送信 | java-mustache-processorによるHTMLテンプレート、6種類のアカウントライフサイクルメール(Q18) |

## Scope Definition & Prioritization

| 決定事項 | 内容 |
|---|---|
| 最初のMVP範囲 | 3つのテスト業務ドメインすべてで一覧・詳細・編集画面(Q1) |
| 権限機能 | Must-have(Q2) |
| メールフロー6種類 | すべてMust-have(Q3) |
| 設定エクスポート/インポート | Must-have(Q4) |
| 複合主キー・ビュー対応 | 最初のMVPに含める(Q5) |
| 着手順 | スキーマ読み込み→内部設定(H2)→一覧画面(Q6) |
| 進め方 | リスクの高いところ(RDBMS間の差異)から着手(Q7) |

## Rough Mockups & Concept Visualization

| 決定事項 | 内容 |
|---|---|
| トップ画面 | 単一業務インスタンス内のテーブル・メニューのCard一覧(複数業務ドメインの並列表示ではない、修正済み) |
| ナビゲーション | make-you-chic-uiのAppShell(サイドバー+トップバー)ベース |
| 権限モデル | ロール(Role)単位でテーブル権限(一覧/詳細/新規/編集/削除)+カラム権限(更新可/表示のみ/非表示)を定義し、ユーザ/グループに割り当て。複数ロール保有時は切替可能 |
| グループ管理 | メンバー編集はインライン(アコーディオン展開)。削除・改名はRefined Mockups以降に先送り |
| アクセシビリティ | WCAG 2.1 AA相当を基本方針 |
| 対応デバイス | デスクトップ主体、レスポンシブ対応は必須ではない |
