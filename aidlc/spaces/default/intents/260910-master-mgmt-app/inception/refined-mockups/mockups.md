## 1. ログイン画面(新規)

Q2回答(A, B, D)に基づき、基本構成 + パスワードリセット導線 + 汎用エラーメッセージのシンプルな構成とする。ロックアウト警告表示(残り試行回数等)は含めない。

```
+--------------------------------------------------------------+
|                                                                |
|                      [Logo] MasterSmith                       |
|                                                                |
|                 +--------------------------+                  |
|                 | メールアドレス            |                  |
|                 | [______________________] |                  |
|                 |                          |                  |
|                 | パスワード                |                  |
|                 | [______________________] |                  |
|                 |                          |                  |
|                 |        [ログイン]         |                  |
|                 |                          |                  |
|                 | パスワードをお忘れですか?  |                  |
|                 +--------------------------+                  |
|                                                                |
+--------------------------------------------------------------+
```

- アクセシビリティ: h1「MasterSmithにログイン」、main landmark、フォームは`<form>`要素、メールアドレス/パスワード欄に`<label>`を明示的に関連付け、キーボードエントリーポイントはメールアドレス入力欄
- 「パスワードをお忘れですか?」リンクは表示のみとし、遷移先の機能自体はOut of Scope(要件未定義のため、クリック時は「この機能は現在ご利用いただけません。管理者にお問い合わせください」という案内を表示する)
- Loading状態: ログインボタン押下後、ボタンを非活性化しスピナー表示
- Error状態: メールアドレス不一致・パスワード不一致・アカウントロック中のいずれの場合も、理由を区別せず「メールアドレスまたはパスワードが正しくありません」という汎用エラーメッセージをフォーム上部にインライン表示する(Q2回答D、Q12回答C)。ロック中であることや残り試行回数は一切表示しない
- Empty状態: 該当なし(入力フォームのため)
- 連続ログイン失敗によるアカウントの一時ロック(FR2.7)の閾値・ロック時間は `application.yml` で設定する(FR3.1のトークン有効期限と同様の方式)。管理画面上に閾値・ロック時間を編集するUIは設けない(レビュー指摘R-01への対応。要件定義書FR2.7の文言「管理画面から設定可能でなければならない」は`application.yml`方式へ修正する必要があり、後続のフォローアップ事項として本ドキュメント末尾のAssumptions & Open Questionsに記録する)

## 2. 初期パスワード設定画面(招待リンクから遷移、新規)

FR2.1「招待メールを受け取ったユーザーは、メール中のリンクから自身のパスワード・氏名を設定して初回ログインできなければならない」に対応する画面。

```
+--------------------------------------------------------------+
|                      [Logo] MasterSmith                       |
|                                                                |
|                 初回パスワード設定                              |
|                 +--------------------------+                  |
|                 | 氏名(必須)               |                  |
|                 | [______________________] |                  |
|                 |                          |                  |
|                 | パスワード(必須・8文字以上)|                  |
|                 | [______________________] |                  |
|                 |                          |                  |
|                 | パスワード(確認・必須)     |                  |
|                 | [______________________] |                  |
|                 |                          |                  |
|                 |     [設定してログイン]     |                  |
|                 +--------------------------+                  |
+--------------------------------------------------------------+
```

- アクセシビリティ: h1「初回パスワード設定」、main landmark、必須項目に`aria-required`、パスワード確認欄が不一致の場合はフォーカスアウト時にインラインエラー
- バリデーション: パスワードは最小8文字以上(FR2.5)。フォーカスアウト時にインライン表示、汎用のスタックトレース等は表示しない
- Error状態: 招待リンクの有効期限切れ・既に使用済みの場合は、フォームの代わりに「このリンクは無効です。管理者に再招待を依頼してください」を表示
- Loading状態: 送信中はボタンを非活性化しスピナー表示
- 成功時: 設定完了メッセージを表示後、自動的にログイン済み状態でトップ画面へ遷移

## 5. 一覧画面(リファイン)

Q4(一括削除のみ)、Q5(アコーディオン展開)、Q8(ツールバーにCSV export/import)を反映する。

```
+----------+---------------------------------------------------+
| Sidebar  |  [テーブル1] 一覧                                    |
|          |  +------------------------------------------+      |
|          |  | 検索条件(主要のみ) [▼ 詳細検索]  [検索][クリア]|      |
|          |  +------------------------------------------+      |
|          |  | ▼ 詳細検索(展開時、同一画面内にアコーディオン表示)|      |
|          |  |   [条件4] [条件5] [条件6] ...              |      |
|          |  +------------------------------------------+      |
|          |  [+ 新規作成] [CSVエクスポート] [CSVインポート]       |
|          |  (選択中: 2件) [選択項目を一括削除]                  |
|          |  +------------------------------------------+      |
|          |  | □ | 列1▲| 列2 | 列3 |         | 操作      |      |
|          |  |---|-----|-----|-----|---------|----------|      |
|          |  | □ | ... | ... | ... |         | [詳細]    |      |
|          |  +------------------------------------------+      |
|          |  ページサイズ[10 ▼]  < 1 2 3 ... 10 >   全123件     |
+----------+---------------------------------------------------+
```

- 詳細検索は「▼ 詳細検索」をクリックすると同一画面内にアコーディオン形式で展開する。ページ遷移は発生しない(Q5回答A)
- 行チェックボックス(□)は一括削除専用。1件以上選択するとツールバー下に「選択中: N件」と「選択項目を一括削除」ボタンが出現する。DELETE権限がない場合はチェックボックス列自体を表示しない(Q4回答A)
- 「選択項目を一括削除」押下時は確認モーダル(削除対象件数を明示)を経て実行する(`interaction-spec.md` 参照)
- CSVエクスポート/インポートボタンはツールバー上、「+ 新規作成」の隣に配置する(Q8回答A)。インポート時のバリデーションエラーは行単位のエラー一覧をモーダルで表示する(`interaction-spec.md` 参照)
- ページサイズ選択(10/20/50/100件、FR5.2)をページング操作部の左側に配置する
- READ権限のないカラムは列自体を非表示、CREATE権限がない場合は「+ 新規作成」ボタンを非表示にする(FR5.3)
- Empty/Loading/Error状態は `wireframes.md` の記載を踏襲する

## 6. 詳細・編集画面(リファイン)

Q6・Q6-follow-upに基づき、楽観ロック競合エラーの提示方法を反映する。

```
+----------+---------------------------------------------------+
| Sidebar  |  [テーブル1] 詳細・編集            [一覧に戻る]       |
|          |  +------------------------------------------+      |
|          |  | (競合検出時のみ)このデータは他のユーザーによって   |      |
|          |  | 更新されています。編集内容を確認し、必要であれば   |      |
|          |  | 画面を再読み込みしてください。                    |      |
|          |  +------------------------------------------+      |
|          |  | 項目1(必須)   [________________]          |      |
|          |  | 項目2         [________________]          |      |
|          |  | 項目3(select) [▼ 選択してください  ]        |      |
|          |  | 項目4(読取専用) 値のみ表示                   |      |
|          |  +------------------------------------------+      |
|          |  [保存]  [キャンセル]                              |
+----------+---------------------------------------------------+
```

- 楽観ロック(更新日時/バージョン列)が定義されているテーブルでのみ、保存時に競合を検出しエラーバナーをインライン表示する(Q6回答A)。当該列が定義されていないテーブルでは競合検出を行わず、後勝ちで上書き保存される(Q6-follow-up回答B。要件定義書FR6.3の文言修正が必要な点は `refined-mockups-questions.md` の Assumptions & Open Questions に記録済み)
- 楽観ロック競合を検出した場合は一覧画面に遷移せず、詳細・編集画面に留まる(FR6.3)。ユーザーは手動で画面をリロードして最新データを確認する(再読み込みボタンの併設や比較モーダルは採用しない)
- その他(フォーム部品、権限による読取専用/非表示、バリデーション、Loading/Error/成功時の挙動)は `wireframes.md` の記載を踏襲する

## 7. ユーザ管理画面(新規)

FR2に対応。一覧画面と作成・編集画面の2画面構成とし、共通エンジン層の一覧/詳細編集の設計思想を踏襲する(ただしユーザ管理は業務データではなく内部設定データのため、共通エンジン層とは別の管理者専用画面として実装する)。

### 7-1. ユーザ一覧画面

```
+----------+---------------------------------------------------+
| Sidebar  |  ユーザ管理                                         |
|          |  [+ ユーザーを招待]                                  |
|          |  +------------------------------------------+      |
|          |  | 氏名 | メールアドレス | ロール | 状態 | 操作  |      |
|          |  |------|--------------|--------|------|------|      |
|          |  | ...  | ...          | ...    | 有効 | [編集]|      |
|          |  | ...  | ...          | ...    | 無効化済み|[編集]|      |
|          |  +------------------------------------------+      |
+----------+---------------------------------------------------+
```

- 「+ ユーザーを招待」から招待モーダル(氏名・メールアドレス・付与ロールを入力)を開き、送信するとFR2.1の招待メールが送信される
- 「状態」列は有効/無効化済み/ロック中を表示。無効化済みユーザーには「有効化」、有効なユーザーには「無効化」操作を提供する(無効化はFR2.3により確認モーダルを経る)
- アクセシビリティ: h1「ユーザ管理」、main landmark、テーブルはtheadで列を示す、キーボードエントリーポイントは「+ ユーザーを招待」ボタン(一覧画面(5.)と同水準の方針を直接記述。レビュー指摘R-08への対応)
- Empty/Loading/Error状態は一覧画面(5.)と同様の方針を踏襲する
- タブレット(768〜1023px)ではテーブルを横スクロール可能なコンテナに収め、列幅の優先度が低い項目(状態等)を非表示にせず横スクロールで参照可能とする(一覧画面(5.)と同様の方針、レビュー指摘R-04への対応)

### 7-2. ユーザ編集画面

```
+----------+---------------------------------------------------+
| Sidebar  |  ユーザ編集              [一覧に戻る]                |
|          |  +------------------------------------------+      |
|          |  | 氏名           [________________]         |      |
|          |  | メールアドレス(読取専用) xxx@example.com    |      |
|          |  | 所属ロール(複数選択) [ロールA] [ロールB] ... |      |
|          |  | 状態           ○有効 ○無効化               |      |
|          |  +------------------------------------------+      |
|          |  [保存]  [キャンセル]                              |
+----------+---------------------------------------------------+
```

- 管理者はユーザーの氏名・所属ロールを更新でき(FR2.2)、無効化操作もこの画面から行える(FR2.3)
- メールアドレスは登録後の変更を不可とし、読取専用表示とする(要件に変更手順の定義がないため)
- タブレット(768〜1023px)ではフォーム項目を1カラムに折り返して表示する(詳細・編集画面(6.)と同様の方針、レビュー指摘R-04への対応)
- アクセシビリティ: h1「ユーザ編集」、main landmark、必須項目に`aria-required`、ロールの複数選択は`role="group"`+各チェックボックスに`aria-label`、状態のラジオボタンには`fieldset`/`legend`で「状態」ラベルを関連付け、キーボードエントリーポイントは氏名入力欄(レビュー指摘R-05への対応)

## 9. 業務メニュー設定画面(新規・概略)

FR1・FR4・FR7.1に対応する管理画面。詳細なフォーム項目・スキーマ編集UIはドメイン設計以降で確定するため、本ステージではタブ構成と概略レイアウトのみを示す。

```
+----------+---------------------------------------------------+
| Sidebar  |  業務メニュー設定                                    |
|          |  [スキーマ・表示設定] [権限(RBAC)設定] [メニュー構成]  |
|          |  +------------------------------------------+      |
|          |  | (選択中タブの設定内容を表形式で表示・編集)         |      |
|          |  +------------------------------------------+      |
+----------+---------------------------------------------------+
```

- 「スキーマ・表示設定」タブ: テーブル/カラム単位の表示名・表示順・書式・編集部品・バリデーション・楽観ロック用列指定(Q6-follow-up)を設定する
- 「権限(RBAC)設定」タブ: ロール・主権限(FULL/READ/NONE/指定なし)・補助権限(CREATE/DELETE)の階層設定を行う
- 「メニュー構成」タブ: 業務メニューのN階層構成を編集する
- アクセシビリティ: h1「業務メニュー設定」、main landmark、タブは`role="tablist"`/`tab`/`tabpanel`
- タブレット(768〜1023px)ではタブをスクロール可能な横並びとし、設定内容のテーブルは横スクロール可能なコンテナに収める(レビュー指摘R-04への対応)
- 詳細なワイヤーフレームはドメイン設計・機能設計ステージで具体化する

## 10. 設定管理画面(新規)

FR11に対応。JSON形式の設定一式(スキーマ定義・メニュー構成・RBAC設定)のエクスポート/インポートを集約する独立画面(Q7回答B)。

```
+----------+---------------------------------------------------+
| Sidebar  |  設定管理                                           |
|          |  現在の設定をエクスポート                             |
|          |  [設定をエクスポート(JSON)]                          |

|          |  設定をインポート                                    |

+----------+---------------------------------------------------+
```

- 設定定義自体に誤り(必須プロパティ欠落等)がある場合はインポートを実行せず、fail fastでエラー内容を一覧表示する(FR1.3、`interaction-spec.md` 参照)
