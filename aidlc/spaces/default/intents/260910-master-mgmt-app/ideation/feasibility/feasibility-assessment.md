# Feasibility Assessment — MasterSmith(マスタ管理アプリ)

## Technical Viability

- 統合対象は既存のRDBMS(PostgreSQL/MySQL/MariaDBの複数対応)のみで、外部の認証基盤や他システムとの連携は不要(Q1)。統合面の技術的難易度は低い。
- 開発チームの技術スタック(backend: Java 25 + Spring Boot + Gradle、frontend: TypeScript + Vite + React、実行可能WARにfrontendを同梱してSpring Bootから配信する構成)は、確立された成熟したスタックであり、技術的な実現可能性は高い(Q5)。
- 想定利用規模は数十名程度(Q4)で、同時接続数もその範囲に収まる見込み。一般的なWebアプリケーションの負荷特性であり、性能面で特別な技術的困難は想定されない。
- 規制・コンプライアンス上の制約がないこと(Q2)、組織的な障害がないこと(Q7)、予算・スケジュール上の厳密な制約がないこと(Q6)から、非技術的な実現阻害要因も現時点では見当たらない。

**総合評価**: 技術的実現可能性は高い。

## Risk Analysis

| リスク | 影響 | 可能性 | 備考 |
|---|---|---|---|
| 複数RDBMS対応(PostgreSQL/MySQL/MariaDB)による方言差異の吸収 | 中 | 中 | 「1カラム1設定レコード」の設定モデルがRDBMS方言差異をどこまで吸収できるかは、後続の設計段階(ドメイン設計・機能設計)で具体化が必要 |
| 実行環境が未定(Q8) | 低 | 中 | 今回のワークフローでは実行可能WARの生成までがスコープであり、実運用投入時の環境要件はスコープ外。OTELエクスポート対応・構造化ログは今回のスコープ内で実装するため、将来の投入は妨げられない |
| 利用規模が数十名程度に拡大(MasterMeisterの約10名規模より大きい、Q4) | 低 | 低 | 一般的なWebアプリケーションの規模であり、現行の技術スタックで十分対応可能と判断 |
